- 64-bit Windows
- JDK **23**, not only a JRE

Set these under **System Properties → Environment Variables**:

```text
JAVA_HOME=C:\Program Files\Eclipse Adoptium\jdk-23...
MAVEN_HOME=C:\Program Files\Apache\Maven
```

Add these to `Path`:

```text
%JAVA_HOME%\bin
%MAVEN_HOME%\bin
C:\Program Files\nodejs
```

Verify in PowerShell:

```powershell
java -version
javac -version
mvn -version
git --version
node --version
npm --version
```

The checked-in VS Code setting is macOS-specific:

```json
"java.home": "/opt/homebrew/opt/openjdk/"
```

Override or replace it in `settings.json` with your Windows JDK path, for example:

```json
"java.jdt.ls.java.home": "C:\\Program Files\\Eclipse Adoptium\\jdk-23.0.x-hotspot"
```

The setting is currently visible in `settings.json:78-86`.

**Project setup**

From PowerShell:

```powershell
cd C:\path\to\Automation-JAV-Client-GEM_QA_CC_PRODUCT_MAPPING
mvn clean install -DskipTests
mvn test -Dtest=TS_BCAA_Claim_Portal_Product_Mapping_JUnit
```

The framework loads configuration from `testConfig.properties:75-125`. The default configuration uses:

```properties

headless=false
parallelExecution=false
```

Use headless execution when needed:

```powershell

```

The Maven documentation also uses `-Dbrowser.headless=true`, but the Java configuration currently uses the property name `headless`; use `headless` for this codebase.

**Access and network requirements**

- Access to the GEM QA/Appian environment
- Required VPN or corporate network connection
- Valid Google/Microsoft login and MFA access
- Outbound access to Maven Central, WebDriverManager downloads, npm, and the tested application
